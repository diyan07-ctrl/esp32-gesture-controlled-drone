# ESC output enablement and motor testing

Four constants in firmware/common/configuration/config.h default false: outputsVerified, powerVerified, propulsionVerified and controllerValidated. They gate LEDC initialization in both the drone and separate motor_test image. No radio/serial command bypasses these gates. Changing flags is not engineering evidence.

Before a controlled propeller-off fixture test, document exact ESC/board/motor identities, regulated rails, verified signal logic levels, startup hold, signal rate/endpoints, no-signal shutdown, GPIO/position/spin mapping and test fixture. ControllerValidated may represent reviewed bench behavior for that exact propeller-off configuration; it is not flight acceptance. Record the context rather than reusing a bench flag as flight approval.

Candidate PWM is 50 Hz, 16 bits, 1000–2000 µs. Safe startup/disarm/fault is **no pulses**; the exact ESC must stop safely on absent signal. During explicit ARMING_CHECKS the drone sends minimum pulses for cfg::armHoldMs before accepting stabilized throttle. No endpoint calibration or automatic arming occurs. If the identified ESC needs different idle/startup behavior, update the output contract and test every transition; do not assume this candidate contract is compatible.

motor_test is a separate propeller-off image, never flight firmware. With gates enabled, ! attaches output channels; 1…4 requests only the selected motor at 5% for at most 1000 ms from the last valid command. x or optional local permit opening stops outputs. Other motors receive minimum pulse during an active test, so independently verify that minimum really stops them. Outside an active test all channels have no pulses. Use the exact ESC startup procedure before tests; the image does not perform universal ESC calibration. Do not flash/test on unidentified hardware.

An MCU stall can leave LEDC generating the prior pulse until reset; the software task watchdog is not independent actuator protection. Resolve and validate this before flight. All propeller/flight work additionally needs measured thrust/current/power margin, PID tuning, actual timing, reviewed airborne failsafe policy and supervised controlled validation.
