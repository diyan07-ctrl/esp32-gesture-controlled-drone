# Ordered verification procedure

Executed software results are in [validation-results](validation-results.md). The steps below are procedures, **NOT EXECUTED** hardware tests in this session. The owner reports earlier COM9/4 MB detection and individual motor tests; those do not prove the new firmware, wiring, flight control or failsafe behavior.

Record firmware commit/configuration, exact device models, instrument traces, wiring photos, timestamp, measured values and pass/fail for every step. All initial motor tests must have every propeller removed. Keep a physical battery disconnect accessible and secure the frame.

1. **Boot/serial diagnostics:** isolate propulsion, verify regulated rails and ground, confirm actual COM port (COM9 was historical), flash the correct board, observe boot/disarmed state and disabled output gates. Reboot/brownout must never arm; capture serial faults.
2. **MPU6050 communication:** first use independent glove_sensors/drone_sensors
   images; both WHO_AM_I registers must read 0x68 (separate from AD0 address).
   Check rails/pullups/readbacks, disconnect failures, calibration/noise/signs and
   actual timing. [Required separate acceptance records](sensor-migration.md).
   Both physical IMU tests must pass before further flight-control integration.
3. **Flex readings:** capture open/bent NVS endpoints; sweep both independently; test rails/disconnection/noisy transitions; validate debounce/hysteresis and every gesture with outputs disabled. Verify calibration is rejected while arm request active.
4. **Wireless:** provision private peers/keys, verify advancing application acknowledgments, commands/status, session restarts, loss estimates and measured latency. Corrupt packets and replay/duplicate sequences with a controlled test transmitter; verify no age refresh. Establish range/interference limits. Host mocks do not execute RF.
5. **ESC signals:** identify exact ESC manual. Scope candidate 50 Hz / 1000–2000 µs outputs only after the enablement review. Verify startup/disarm/fault zero duty, explicit arming minimum pulse and bounds; confirm no-signal means motor stop on this ESC. Inspect channel assignment and jitter under worst workload.
6. **Individual motor output:** props removed, secured fixture, low-energy controlled supply where compatible. Build motor_test; all four output gates still apply. Send ! to initialize, then 1/2/3/4 for one motor at 5% for no more than 1 s; x stops. Confirm actual ESC startup requirements first. No flight functionality exists in this image. Serial loss must expire the command. Never use it with propellers.
7. **Numbering/rotation:** front marked, top view: M1 FR GPIO25 CCW; M2 FL GPIO26 CW; M3 RL GPIO32 CCW; M4 RR GPIO33 CW. Confirm one at a time, independent of labels, and update config if measurements disagree. Match props only after all propeller-off tests; no prop test is authorized by this procedure alone.
8. **Physical IMU response:** record roll/pitch/rate signs while manually moving the frame. Inject setpoints with output inhibition and compare calculated corrections: positive roll increases left motors, positive pitch front motors, positive yaw CCW motors. Verify calibration, vibration/filtering and timing under load.
9. **Safety state machine:** power-up disarmed, arm held at boot rejected, fresh release then explicit hold, high throttle rejected, missing output gate rejected, sensor failure and timing injection shutdown, battery invalid/low if fitted, ordinary disarm, emergency priority even amid normal packet traffic, terminal latch through reconnect. Test output edges, not just LEDs/logs. Validate MCU stall/reset with scope; hardware watchdog limitation remains.
10. **Communication loss:** while secured/props off at minimum validated output, interrupt transmitter RF/power and verify accepted-command age >200 ms causes deliberate latched shutdown within measured loop/ESC latency. Restore communication and prove no re-arm. Repeat during arming, duplicates, corrupt traffic, session restart and emergency/ordinary race. Record RF/loop/PWM timing.

Supplementary HC-SR04: verify 5 V Echo protection and actual GPIOs, scope 12 µs trigger/echo, no-target timeout, stale health, filtering and known distances under representative tilt/surfaces/rotor noise. It has no control authority. Optional battery monitoring requires DMM comparison, divider-fault tests, loaded sag/transient characterization and an independently reviewed low-voltage policy.

Before flight: independently validate power, propulsion/thrust/current/thermal behavior, mass/CG, sensor axes/calibration, actual controller/actuator timing, PID tuning, saturation recovery and failsafe risks in controlled supervised conditions. Simulation is not flight validation. No autonomous flight test is authorized or performed here.
